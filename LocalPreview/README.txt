Majsoul-modLauncher 0.6.7
======================

0.6.7 修复 Steam 版启动后重新拉起游戏、丢失本地预览的问题。
启动时根据 Steam 安装记录设置游戏的应用环境，并确认进程持续运行后再显示成功。
Steam 版请先登录 Steam，再选择 Steam 安装目录下的 Jantama_MahjongSoul.exe。

0.6.6 支持游戏内大小头像替换。每个 Mod 根目录可放入 smallhead.png（小头像）
和 bighead.png（大头像），两者均可选。启动器 Mod 卡片可直接选择对应 PNG。
按角色、皮肤 ID 匹配，缺少的头像保留原图；F10 重载，F11 恢复原头像。
头像与立绘、动态图集共同计入 1024 MiB 预算。完整启用需使用新版 EXE 和 DLL。

0.6.5 将全部启用模组的 PNG 解码预算提高至 1024 MiB。
新版 EXE 与 DLL 配套使用，下次通过新版启动器启动游戏时启用新上限。

0.6.4 在皮肤加载完成与重新显示时立即替换，首帧显示替换纹理。
动态皮肤继续复用原骨骼和动画，轮询仅用于布局跟随与补查。

图形启动器
双击 Majsoul-modLauncher.exe。MaJmods.dll 与 EXE 保持同目录，运行数据存放在 MaJmods 文件夹。
内置 129 位角色头像与 526 款皮肤资料，包含泠星与《葬送的芙莉莲》联动角色。
运行时不依赖素材原始目录，不需要复制整套 Majsoul_Skins。
角色卡片右下角的数字表示“已启用 / 已安装”的 Mod 数量；已配置角色优先显示。
可按角色名称或 ID 搜索，也可筛选“已配置”。
在角色一览顶部点击“全部启用 Mod”或“全部关闭 Mod”，可一次保存所有角色的启停设置。

点击角色查看独立 Mod，可启用/停用、替换 PNG、打开对应文件夹。
“添加自定义图片”可以选择角色、具体皮肤、Mod 名称和 PNG，不会自动覆盖其他皮肤。
同一角色和皮肤组合只启用一个 Mod，开启另一个相同组合会停用原 Mod。
批量启用时，同一组合优先保留已启用的 Mod。
游戏已通过本工具启动时，界面保存变更会请求重载；F10/F11 仍保持原有作用。
上方“重载图片”和“恢复原图”与游戏中的 F10/F11 采用同一套显示开关。
已有的其他角色/皮肤 ID 仍可用目录与 mod.ini 配置；未内置的角色会使用名称首字占位。

点击左下“启动游戏”，首次选择雀魂 EXE，之后从 MaJmods.ini 读取已保存的路径。
启动设置中可重新选择路径，并开关“启动成功后自动关闭窗口”。
默认成功后倒计时 5 秒关闭，可点击“保留窗口”继续管理 Mod。
若游戏已经运行，会显示运行状态；需要启动新版 DLL 时请先退出旧游戏。
角色、皮肤及装扮仍在游戏原有页面选择，本机选择按账号保存。
--pick / --choose-game 重新选择并启动；--game <EXE路径> 指定路径并启动；
--close-after <秒> 设置倒计时，0 保留窗口；--help 查看参数。

包内包含两个二之宫花（200017）Mod：默认皮肤（401701）与纯白午后（401710）。
图片保持独立匹配，并跟随原图尺寸、位置和裁切关系。

自定义图片目录
所有路径相对于工具 EXE 所在目录，不是游戏目录或快捷方式的工作目录：
  .\MaJmods\mods\角色名称\mod名称\mod.ini
  .\MaJmods\mods\角色名称\mod名称\custom.png
首次运行会在 .\MaJmods\mods\二之宫花\默认替换\ 生成示例。
默认示例仅匹配二之宫花默认皮肤 401701，不替换契约或其他皮肤。
示例图片为此前提供的 PNG。支持中文目录、图片文件名及透明 PNG。
目录名只用于整理，实际按 mod.ini 中的 ID 匹配。
可创建多个角色目录，每个角色下创建多个 mod，每个 mod 放自己的配置及图片。
mod.ini 使用 UTF-8；# 或 ; 开头为注释，不要在数值后追加注释。

单一皮肤的 mod.ini 示例（默认示例，只替换默认皮肤）：
  enabled = 1
  character_id = 200017
  skin_id = 401701
  image = custom.png

角色通用示例（仅有意替换这个角色所有皮肤时，放在另一个 mod 目录）：
  enabled = 1
  character_id = 200017
  skin_id = 0
  image = 角色通用.png

character_id 必填。skin_id=0 或省略表示角色通用；其他正整数仅匹配指定皮肤。
兼容旧字段 character、skin；同一 ID 不要同时写新旧字段。
image 相对于当前 mod 目录，省略时使用 custom.png。
皮肤专用配置优先于同一角色的通用配置。
只替换一个皮肤时，不要同时启用该角色的 skin_id=0 配置。
同一角色 ID + 同一皮肤 ID 只能启用一个 mod；重复会拒绝本次重载。
enabled=0 停用；也可删除 mod 目录或 mod.ini，然后按 F10。

动态皮肤（0.6.3）
静态视图继续使用 image 指定的立绘。动态视图保留游戏原骨骼、动画与分层。
在对应 mod 目录下增加 spine\layerN\原图集名.png 即可替换该层贴图，例如：
  悸动之夏（400706）\spine\layer2\bamuwei_xr.png
优先按图集名和尺寸匹配运行时图集，layerN 用作层号提示。
源素材目录的 layer2 可能对应运行时第 1 层，名称与尺寸唯一匹配时会自动映射。
图集名（不含 .png）及宽高必须与原图集一致，并使用相同的图块排布。
目前每层支持一张图集，PNG 图集计入 1024 MiB 解码预算。
替换该实例的 OverrideTexture，多 CanvasRenderer 同时更新 CustomTextureOverride。
F11 和重载会恢复两种纹理覆盖的原值，未配置的层继续使用原贴图。
未提供图集、名称/尺寸不匹配或使用特效渲染器的动态视图继续显示原动画。
F11 恢复原贴图，F10 重新载入，静态 PNG 不再覆盖动态视图。

快捷键（游戏窗口在前台）
F10：重新扫描全部 mod，读取修改后的配置和图片，启用自定义显示。
     新增、修改、删除和停用均无需重启或重新编译。
     坏图片、错误配置或重复匹配会整体取消本次重载，保留当前显示。
F11：统一关闭全部自定义立绘并恢复原图。本次会话跨场景保持关闭，F10 可再启用。
     不退出游戏、不清除保存的角色和皮肤选择；下次启动按 enabled 加载。

范围与布局
覆盖大厅、宿舍（寮舍）角色大图、服饰预览、友人房本人立绘、对局本人演出及结算立绘。
不同角色及不同皮肤可同时显示各自图片，对手即使用同一角色也不会替换对手图片。
牌谱、观战和教程不替换。静态 PNG 不改变头像、骨骼动画、表情或 3D 模型。
每个 mod 可独立添加布局项，修改后 F10：
  lobby_height、lobby_x、lobby_y
  dorm_height、dorm_x、dorm_y
  dorm_preview_height、dorm_preview_x、dorm_preview_y
  room_height、room_x、room_y
  match_height、match_x、match_y
  ending_height、ending_x、ending_y
默认直接跟随游戏原图的实际尺寸、位置、缩放和裁切层级，保持自定义图片宽高比。
height 可指定原图局部坐标中的高度，x/y 为相对原图位置的偏移，支持小数。
不需要微调时请省略这些布局项；旧版的固定 lobby_height/x/y 可删除以启用自动对齐。
源图片的人物姿势、边缘留白不同，局部内容可能无法与原画完全重合。
PNG 尺寸上限 4096 x 8192，全部启用图片解码后合计上限 1024 MiB。

升级与运行数据
升级时同时替换 EXE 和 DLL。如果只有旧的 MJLocalPreview 数据目录，启动器会将它改名为 MaJmods。
MaJmods 已存在时，启动器直接使用该目录。
如果只有旧的 MJLocalPreview.ini，启动器会将它改名为 MaJmods.ini，保留已保存的游戏路径。
首次出现 mods 目录时，从同一工具目录下旧 CustomSkins 复制图片和配置；旧文件保留。
只在 mods 从未存在时导入或生成示例，之后不会覆盖已有图片和配置。
若旧工具位于另一个目录，可手动把旧图片和配置放入新的 mod 目录，配置重命名为 mod.ini。
运行管理脚本 MaJmods\custom_skin.lua 在启动时更新。日常修改请放在 mod.ini。
图片经本地内存传给游戏，不再生成 custom.rgba。
错误日志 custom-skin-进程ID.log 与启动日志 preview-进程ID.log 保存在 MaJmods。
普通物品目录位于 MaJmods\max_data.yaml，仅增加物品时更新该文件并重启即可。
运行数据首次由程序生成。升级时保留数据文件夹及路径记忆 INI。
启动器偏好和内置启动组件位于 MaJmods\launcher，后台组件会随 EXE 自动更新。
启动详情见该目录的 launch.log。界面使用 Windows 自带的 .NET Framework 4.x。
不要同时加载旧 MJCustomSkin 验证 DLL；必须退出旧游戏后用新版 EXE 启动，才能加载新版 DLL。

支持 32 位 Windows 雀魂，无需另装 VC++ 运行库。
仅影响本机显示，不修改服务器资产，其他玩家仍看到服务器记录的外观。
游戏更新改变接口或场景逻辑时仍可能需要更新工具，缺失资源不会凭空生成。
